# Crew 0.20.0

Find the right tasks and make precise review decisions. This release adds label
filters, stable hold ages, compact claim cards, review image previews and structured
options. One data migration requires a complete backup before upgrading. Run
`skill` once and refresh MCP tool schemas. Protocol 3 and the managed webhook
instruction block are unchanged; delivery does not pause for this upgrade.

## Tasks

- Combine a case-insensitive label filter with assignment, hold and release
  filters. Labels have counts, clicking a card label filters the board, and filters
  stay in the address for reload, back/forward and sharing.
- Home tiles open the tasks they count. **On hold over 3 days** has its own
  removable filter, excluding terminal tasks. Hold age uses a server-managed
  timestamp that survives edits and comments; older records start from their
  pre-upgrade update time, an approximation rather than a recovered hold date.
- See held duration and sort oldest-held tasks first.
- Claims use a compact tool/countdown chip with an expiry warning. Full session
  attribution and claim times remain available in details. Ready appears only on
  To do cards, and labels matching the assignee are hidden on cards while remaining
  searchable and filterable.
- A shared **Implement** agent can handle code tasks labeled by repository. The
  session's brief selects the repository and its instructions; one agent per
  repository is still supported.

## Reviews

- Review the immutable attachment snapshot through inline images and a gallery,
  with full-size previews. Draft line breaks stay visible.
- Requests that mention local image/document paths fail with
  `draft_references_unattached_files`. Attach files to Crew and reference them as
  `attachment:ID` before requesting review. Older reviews show a missing-file warning.
- Submit alternatives with optional `options: [{key, label, body}]` in
  `review.request`. Each option is frozen with the review. The owner can record
  exactly which draft and platform they approve or reject, with optional notes.
- `review.decide` accepts `option_decisions: [{key, decision, note}]`. Approval
  requires explicit choices and at least one approved option. Activity, review
  history and read-only SQL preserve the choices. Reviews without options retain
  their existing behavior. Agents still decide only on explicit owner delegation.
- Approval never posts, sends, pays or marks a task Done.

## Upgrade

Follow [Crew 0.19.0 to 0.20.0](../upgrades.md). Back up the complete stopped project
and private webhook key before replacing the binary or image. Upgrade paired
clients to match. Older binaries refuse the migrated database; rollback restores
the complete pre-upgrade backup, losing changes made since it.
