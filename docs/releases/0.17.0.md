# Crew 0.17.0

On hold instead of Waiting, comments with Markdown and screenshots, label chips, and
fixes for review requests and stranded wakes. No data migration, no protocol version
change and no new managed instruction block, so webhook delivery is not paused.
`capabilities_digest` changes. Run `skill` once after upgrading.

## On hold

- The reader calls readiness **On hold** and **Ready**; the word "Waiting" is gone.
  The task editor has **Hold** and **Hold reason** fields with a one-line explanation:
  on hold, nobody is woken and a person decides; Ready, the assigned bot may act.
- One wake rule, stated in the reader, capabilities, MCP instructions, skill and docs:
  an on-hold task never wakes a bot, whatever changes (creation, assignment, comments).
  Only Ready tasks wake.
- Putting a task on hold always works, even while an execution is live. It cancels the
  execution (outcome `put_on_hold`, shown in Activity) and makes queued wakes stale. A
  work client needs no execution proof when it only changes the hold.
- Crew now says why it held a task: "Draft edited", "Review withdrawn" or "Bot hand-off
  limit reached". Going Ready clears the reason.
- Cards show an On hold chip with its reason on hover; Done tasks show no hold chip.
  The Tasks board filters by On hold or Ready alongside the agent filter, kept in the
  address, and Home counts tasks on hold for more than 3 days.
- Writes and the `readiness` read filter accept `on_hold` as an alias; reads still
  return `waiting` or `ready`.

## Comments

- Comments render Markdown like descriptions, with `attachment:` screenshots inline
  that open full size. Raw HTML is shown as text.
- The comment box accepts paste, drag and drop and Attach files; Add comment waits for
  uploads.
- `task.comment` takes files like `task.create` (`attachment:new-N` placeholders; MCP
  `crew_write` base64 within 5 MiB per call; CLI `write --file`). Files become
  attachments of the task.
- Comment bodies are now checked like descriptions: an `attachment:ID` must name an
  active attachment of the same task, and `data:` images are refused.

## Reviews and executions

- A worker that requests review on the task it is executing, with its execution proof,
  now completes its execution (outcome `review_requested`) instead of invalidating it.
  Its final fenced comment and a later `execution.complete` (without `mark_done`) are
  still accepted, so human-gated work closes cleanly.

## Stranded wakes

- Connect lists **Wakes not received**: parent-bridge wakes past their deadline with no
  receipt, on open tasks that weren't self-dispatched. Those tasks show "Wake not
  received". Nothing is retried automatically.
- `crew_read {collection: "webhook_bridges", overdue: true}` returns the same list.

## Reader

- Task labels are chips: type and press Enter, comma or Tab, pick from labels already
  in use, paste several at once, remove with × or Backspace. Duplicates are refused.
- Home's status cards respond to hover and keyboard focus, and the whole card is the
  link.

## Server

- Built on `pocketcontext-core` 0.2.0: Crew supplies the OAuth scope, refused earlier
  schemas, hosted budget, public body limit and sign-in email values core used before,
  so connected clients see no change. The synced database is written back at most one
  minute after the oldest unsaved change.

## Upgrade

Follow [Crew 0.16.0 to 0.17.0](../upgrades.md): replace the binary or image, upgrade
paired clients, run `skill` once and refresh MCP connector tool schemas.
