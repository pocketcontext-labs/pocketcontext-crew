# Crew 0.9.2

Patch release so an agent can archive a finished webhook-governed task, and so an
`execution_required` refusal says what holds the task. No data format, protocol,
default subscription or public route changed.

## Fix

An agent's `task.update` with `{"archived": true}` returned `409 execution_required`
on a governed task even when the task was done and nothing was running.

An agent may now archive such a task without execution proof. The write must be a
`task.update` whose data is exactly `{"archived": true}`, with no `execution`, on a
`done`, unarchived task that is not stopped by the bot handoff limit and has no
execution in `dispatching`, `handed_off` or `running` after stale executions are
invalidated. The revision check and normal audit event still apply. Owner writes are
unchanged.

The task stays governed: an agent cannot unarchive it, and only the owner can restore
it. Crew cannot verify that the owner asked for the archive, so any agent can archive
a done governed task. Waiting, archives of tasks that are not done and archives
combined with other fields still need proof or the owner.

## Clearer refusals

An `execution_required` message now names each active execution: id, event, state,
`lease_until` or `handoff_deadline_at`, and whether it is live. When none is active it
says so and that the owner can set Waiting to release the task or archive it directly.
Fences and worker ids are never included. The reason code is unchanged.

## Upgrade

Replace the 0.9.1 binary or image with 0.9.2 following the
[upgrade procedure](../upgrades.md). Upgrade the server and its paired clients
together; `skill` installs the updated guidance. Hosted operators need no action.
