# Crew 0.21.0

Share frozen pages by link, edit session instructions, and use a calmer task
board. Two data migrations need a complete backup before upgrading. Run `skill`
once and refresh MCP tool schemas. Protocol 3 and the managed webhook instruction
block are unchanged, so delivery doesn't pause for this upgrade.

## Artifacts: pages shared by a secret link

- An **artifact** is a frozen page you share with someone outside Crew by a link,
  with no account or password. In a note, **Share as artifact** creates a draft
  prefilled from that note. Agents can also compose one from several notes with
  `artifact.create` / `artifact.update` (title, Markdown body, images and the
  source notes or tasks).
- **Only you publish.** Agents create and edit drafts. Publishing, replacing the
  published content and revoking happen only in your browser, and work clients get
  HTTP 403 for them. MCP, `crew_read` and SQL never return the link.
- The new **Shared** page lists every artifact with its status, link and Copy
  link, publish time, views and sources. Its actions are Publish, Replace content,
  Edit draft and Revoke. The Publish button says it plainly: anyone with the link
  can view it until you revoke it.
- **Snapshot rule.** Publishing copies the title, body and images. Editing a
  source note never changes the page. Edits to a published artifact's draft show
  as "Changes not live" until you choose Replace content, which keeps the same link.
- **The public page** at `/a/<token>` uses a random 32-character token. It shows
  only the title, body and images, with no script, no Crew navigation and no links
  back into Crew. It sends noindex, no-referrer, no-store and a strict content
  security policy, and is rate-limited. Revoking takes effect at once: the page and
  its images answer the same plain 404 as an unknown link. Publishing again gives
  a new link.

## Session instructions you can edit

- The instructions a coder session reads (Start a session) are now saved in Crew
  per manually started agent, with immutable revisions. The built-in text stays
  the default you can restore.
- The dialog explains this, shows "Revision N · edited by X, date", and offers
  **Rewrite with an agent**, the recommended path. It copies a prompt for Build or
  a coding session to read the current text, agree the change with you and save it
  with the expected revision. The dialog also has **Edit** for small fixes,
  **History** with Restore, and **Restore default**.
- Agents read the instructions and their revision with `crew_read`
  `{collection:"session", agent}`, and history with `session_revisions`. They save
  with `crew_write` `session.update` (`instructions`, `restore_revision` or
  `restore_default`, with `expected_revision`); a stale revision is refused with
  409. Every change is in the history and the activity feed. Copy prompt always
  leads to the latest saved revision.

## A calmer task board

- The toolbar shows only search, the agent filter and one **Filters · N** button.
  The panel holds readiness (including on hold over 3 days), labels, status,
  release and sort.
- Each filter that's set is a removable chip under the toolbar, with a task count
  and **Clear all**. The separate release dropdown is gone. Click a release header
  in the Done column, or type `release:0.20.0` in search (also `label:`, `agent:`
  and `status:`; press Enter to turn them into chips).
- Filters stay in the address, and every Home tile opens the board with matching
  chips and the same count.

## Upgrade

Follow [Crew 0.20.0 to 0.21.0](../upgrades.md). Back up the complete stopped
project and private webhook key before replacing the binary or image. Upgrade
paired clients to match. Older binaries refuse the migrated database, and rollback
restores the complete pre-upgrade backup, losing changes made since it. A reverse
proxy that filters paths must pass `GET /a/*` for shared pages.
