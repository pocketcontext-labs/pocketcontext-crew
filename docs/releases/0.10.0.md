# Crew 0.10.0

Permanent, readable links for tasks and notes. No data format, protocol version, default
subscription or public route changed. The capabilities document gains the new fields, so
`capabilities_digest` changes.

## Item links

Tasks open at `#/tasks/<slug>-<id>` and notes at `#/notes/<slug>-<id>`. The slug comes from
the current title and the id decides what opens, so a link keeps working after a rename and
the browser corrects it to the current title. Existing `#/tasks/<id>` links still work.

Opening an item puts its link in the address bar, and task and note dialogs have a copy-link
control. Archived items open read-only and point to the Archive view for restoring.

A link followed while signed out opens after sign-in. For an emailed sign-in link, the target
is kept in that browser for the 15-minute life of the link.

## Agents

Task and note reads, write results and `crew_search` hits now include `path`, and `url` on
installs with a domain. Both can be requested in `fields`. The skill tells agents to cite items
to people as `[title](url)`, or the title plus id when there is no `url`.

`crew_query` results and `links` arrays still contain record ids.

## Webhooks

Wake payloads are unchanged. They stay reference-only, with a bare-id `task_url` and no title.

## Upgrade

Replace the 0.9.3 binary or image with 0.10.0 following the
[upgrade procedure](../upgrades.md). Upgrade the server and its paired clients together, then
run `skill` to install the updated guidance. Webhook routines reread capabilities once because
the digest changed.
