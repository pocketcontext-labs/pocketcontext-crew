# PocketContext Crew 0.1.1

Crew 0.1.1 improves hosted bulk operations and preserves retry information through
HTTP, MCP and the CLI. It adopts the relevant PocketContext rate-limit fixes
without changing Crew's data model or owner/agent permissions.

## Hosted bulk work

Authenticated API operations share a bounded account budget of 1,200 operation
units, replenished at 100 units per second. Crew reads and writes cost one unit;
inherited evidence batches reserve their maximum size before execution. Tokens,
reported agent names and run keys do not create extra budgets. Anonymous and
sign-in protections remain in place. Native and private local serving do not
acquire the hosted budget. See [rate limits](../rate-limits.md).

Throttle responses carry retry headers and structured metadata. MCP tools return
clear retry instructions, including when an inherited evidence batch wraps a 429
inside HTTP 400. CLI errors retain staging context and same-run resume guidance.
Clients return rate-limit information promptly rather than making immediate
retries during the advertised cooldown; existing temporary-service retries remain.

Crew notes and tasks still use revision-checked custom operations. Generic REST
and batch writes to Crew records remain forbidden. Owner-only review decisions,
immutable history, archive/restore, OAuth consent and the single-writer storage
contract are unchanged. Ordinary Crew operations do not use staging run keys.

## Native client compatibility

This release also includes the previously deployed OAuth compatibility update:
exact localhost callbacks and validated reverse-domain native schemes are
supported, with explicit operator exceptions for otherwise unsupported callbacks.
PKCE, exact callback matching and owner consent remain required.

## Installation and upgrades

Use the version-bound installers and checksums from this repository's v0.1.1
release. Native installation is described in [the Linux service guide](../native-install.md).
Stop the existing service cleanly and verify a complete backup before replacement;
set the installer's explicit replacement version to the version actually observed.
Preserve the project, private runtime paths and service configuration. No data
conversion is introduced by this release. Do not initialize over an existing project.

Hosted upgrades require the complete verified pre-upgrade backup and stop-first
replacement described in [hosting](../hosting.md). Use the tested immutable image
digest recorded with the deployment or the updated Crew setup prompt.

The release workflow validates native binaries on Linux AMD64/ARM64, macOS ARM64
and Windows AMD64, verifies published archive checksums, and tests the installed
assets. Hosted image publication separately requires native container lifecycle
and populated backup/restore checks. Review the actual workflow results; these
checks do not prove owner inbox delivery or third-party client sign-in.
