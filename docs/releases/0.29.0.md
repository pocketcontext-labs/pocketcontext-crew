# Crew 0.29.0

Links in text: record ids and Crew addresses written in notes, tasks, comments and
drafts become links titled with the record they name, and the dialog walks back and
forward through the records opened. No data migration, protocol, managed block,
skill or capabilities change.

- **Bare ids read as titles.** Wherever the reader renders Markdown (note Read
  views, task descriptions, drafts, comments, agent briefs, reviews and the Shared
  page), a 15-character record id becomes a link showing its record's title, with
  the kind and id in the tooltip. Ids that name nothing readable stay plain text,
  as do ids inside code and existing links. Stored text never changes; Edit still
  shows the raw ids.
- **Every reader collection.** Tasks, notes, reviews, buckets, agents, artifacts,
  attachments, comments, other task and note activity, and note and session
  revisions resolve. Buckets and agents get links of their own
  (`#/buckets/<slug>-<id>`, `#/agents/<slug>-<id>`) that open their Edit dialog;
  a file opens its task's or note's viewer (`?file=<id>`), a comment opens its
  task's Comments tab at that comment (`?comment=<id>`), and an artifact opens the
  owner's Shared page entry, never its public link. Webhook, execution,
  upload-link and settings records are never resolved.
- **One request per page.** The reader resolves every id on screen in one batch
  (`crew_read` route, collection `references` with up to 100 `ids`), returning only
  titles, paths, `url` with a domain, and state; never bodies, tokens or
  credentials.
- **Any kind of link.** A pasted address of this Crew install opens in the app,
  titled with its record (`#/reviews/<id>` and `#/artifacts/<id>` read as their
  Approvals and Shared pages). Other `http` and `https` links open in a new tab with
  `noopener noreferrer`, long ones shortened with the full address in the tooltip;
  `mailto:` links stay clickable, and other schemes such as `javascript:` are
  never links.
- **Back and forward.** A link opens its record in the same dialog and adds a
  history entry. Back and forward buttons sit before the dialog title and never
  move (disabled when there is nowhere to go), and the browser's Back and Forward
  walk the same trail. A reload keeps the current record, closing returns to the
  page underneath, and following a link with unsaved changes asks first. Every
  record dialog keeps one size, whatever it shows.

## Upgrade

Replace the binary or image and upgrade paired clients to 0.29.0; see
[Crew 0.28.0 to 0.29.0](../upgrades.md). From 0.27.2 or earlier, follow the earlier
notes first.
