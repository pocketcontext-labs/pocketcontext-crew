# Crew 0.3.0

Crew can notify an external agent when an assigned task is ready. Configure its
HTTPS receiver, authentication and subscriptions directly through the shared MCP
connection. Saving configuration sends nothing; enablement, tests and backlog
catch-up are separate operations an assistant can perform within an authorized
setup request. Human review decisions remain owner-only.

Tasks have explicit readiness. Existing and newly created tasks default to
waiting; assignment alone does not wake an agent. Create or update a task with
`readiness: "ready"` when its prerequisites are satisfied. An optional single
triage destination handles ready unassigned work. The board shows readiness and
unassigned or invalid assignments.

Delivery uses a transactional outbox, bounded retries, stable event IDs and task
generations. Events are invalidated when work becomes ineligible. Restoring a
backup changes the delivery epoch and pauses delivery. Credentials are encrypted
and excluded from ordinary reads and audit events; outbound connections enforce
public HTTPS destinations and reject redirects.

One-prompt setup depends on the receiving harness: it must securely provide its
endpoint and credentials, and implement the documented receiver contract.
Generic webhook support is not evidence of safe tests, deduplication or serialized
task execution. No real Grok Bot integration is certified by this release.

See [webhooks](../webhooks.md) for setup, API operations, receiver requirements
and recovery. Keep a verified complete stopped backup and matching previous
binary before upgrading; rollback uses that complete backup, not an older binary
against the migrated database. This release also includes the standalone Crew
model and legacy-knowledge preservation introduced in 0.2.0.
