# Crew 0.16.0

Attachments: tasks and notes can hold files, and screenshots show inline between the
steps of a bug report. This release has one data migration; back up before upgrading.
No protocol version or managed instruction block changed, so webhook delivery is not
paused. `capabilities_digest` changes.

## Files on tasks and notes

- Attach files with the upload button, by dragging several at once or by pasting, in
  task and note dialogs, including New task and New note before the item exists.
- Up to 20 MB per file and 20 active files per task or note; any file type. PNG, JPEG,
  GIF and WebP are recognized by their content and shown as images; everything else is a
  download. SVG and HTML are never rendered.
- Removing a file archives it; it can be restored and nothing is deleted. Files never
  change: a new version is a new attachment. History shows who attached or removed what.
- An instance storage limit (default 5 GiB, archived files included) is shown and edited
  under Files on the Connect page.

## Screenshots inline

- Pasting or dropping a file into a description, note or draft attaches it and inserts
  `![name](attachment:ID)` at the cursor; Save waits for uploads to finish.
- Inline images load a downscaled copy, capped at 70% of the screen height, and open a
  full-size view with arrow keys between images. Video and audio references become
  players.
- A reference may only name a file of the same task or note. Removed files show
  "Image removed", others "Image unavailable"; images from other sites are never
  loaded, only linked, and embedded `data:` images are refused.
- Board and note cards show the first image as a small thumbnail.

## Previews

- Text, logs, code, JSON (formatted), CSV (first 500 rows as a table) and Markdown up to
  2 MB; video and audio playback; PDF pages with page navigation and zoom, rendered by
  pdf.js loaded only when a PDF opens, with scripts inside PDFs never run. Other files
  download.

## Reviews

- A review records the task's files and their checksums. Adding, removing or restoring
  a file withdraws a pending review, so an approval covers exactly the files you saw.

## One-time upload links

- From a task or note, create a link to send screenshots from a phone that isn't signed
  in: it expires (15 minutes by default, 24 hours at most), takes one batch of files,
  can only upload and can be revoked under Files on the Connect page. Files arrive "via
  upload link" and wake no one. Only the owner can create links.

## Agents

- CLI: `attach FILE… --task|--note ID`, `write … --file PATH` (fills
  `attachment:new-N` placeholders in one step) and `attachment ID --out FILE`, which
  verifies the checksum and never overwrites a file.
- MCP: the new read-only `crew_attachment` tool shows a task's screenshots as images (up
  to 6 per call) and reads text files; `crew_write` adds files as base64 (about 5 MB per
  call). Agents get no download links, and Crew never fetches a file from a URL.
- Agents that only see a screenshot in chat can't re-upload it: the skill tells them to
  file the task and ask you to paste the screenshot into its link.
- Run `skill` once after upgrading; routines reread capabilities once.

## Security

- Files are read only when signed in; on a domain only the protected file read and the
  upload-link endpoints are added to the public route allowlist. Files are served with
  nosniff and a sandbox policy; anything that isn't a verified image downloads.
- Upload links store only a hash of their token, check it from a header before reading
  the request, limit request size and concurrency, and rate-limit unknown tokens
  separately from valid links.

## Upgrade

Follow [Crew 0.15.0 to 0.16.0](../upgrades.md): take a complete backup, replace the
binary or image, upgrade paired clients, run `skill` once and refresh MCP connector
tool schemas. A reverse proxy must allow request bodies of at least 90 MiB. An older
binary refuses the migrated database; rollback means restoring the backup.
