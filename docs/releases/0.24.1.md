# Crew 0.24.1

Two fixes. No data migration, protocol, managed block, skill or capabilities
change.

- **Request changes wakes the bot again.** Deciding Request changes returned the
  task to In progress but kept it On hold when it already was (new tasks start On
  hold, and a draft or file change that withdraws a review puts it on hold), so the
  assigned bot was never woken. The decision now also makes the task Ready and
  clears the stale hold reason, so the assignee wakes with `review_outcome` and
  can read the decision note. Withdrawing, approving and rejecting keep the task's
  readiness as before. A work client deciding on a task stopped by the bot
  hand-off limit leaves it on hold; the owner's decision resets the limit as any
  reader write does.
- **Cancelling a file picker keeps Edit task open.** Cancelling the Attach files
  (Comments) or Add files picker sent a cancel event that closed the dialog and
  lost a half-written comment, notably on macOS. Dialogs now close only on their
  own Escape or a real backdrop click, and ignore a stray Escape or click right
  after a picker closes.

## Upgrade

Replace the binary or image and upgrade paired clients to 0.24.1; see
[Crew 0.24.0 to 0.24.1](../upgrades.md). From 0.23.1 or earlier, follow the
0.23.1 to 0.24.0 notes first.
