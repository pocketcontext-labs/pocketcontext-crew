# Crew 0.7.1

Patch release fixing remote client invitations.

## Fix

The client setup prompt printed by `tunnel invite` was inherited unchanged from
PocketContext. It told the client agent to install "PocketContext 0.24.0" and
linked to `v0.24.0` release, README and installer URLs in the Crew repository,
none of which exist. Client installation from any invitation generated by Crew
0.7.0 or earlier therefore failed. The prompt also told Windows clients to set
`POCKETCONTEXT_INSTALL_DIR`, which Crew's installer ignores; it reads
`CREW_INSTALL_DIR`.

Invitations now name PocketContext Crew and pin the release that generated them,
with its own release page, README and `install.sh`/`install.ps1` links. The pin
lives in one place and the build fails when it differs from the release version,
so a later release cannot ship a stale prompt.

`docs/https.md` also no longer suggests a setup request for PocketContext 0.24.0.

## Who is affected

Owners who paired, or tried to pair, a remote client with `tunnel invite`. Local
use, MCP connections and hosted instances are otherwise unchanged. There are no
database migrations.

## Upgrade

Replace the 0.7.0 binary or image with 0.7.1 following the
[upgrade procedure](../upgrades.md). If a client agent failed with an earlier
invitation, generate a fresh invitation with `tunnel invite` after the host runs
0.7.1 and give the client agent the new prompt. Already connected clients keep
working, but client and server must report the same release: upgrade the client
binary to 0.7.1 and restart its managed forward as the prompt describes.
