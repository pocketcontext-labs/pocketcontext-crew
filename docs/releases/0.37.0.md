# Crew 0.37.0

Every help panel can be hidden with the same "Don't show this again" box, Settings
brings all help back, and record ids written in inline code become links. One data
migration (back up first); no protocol or managed block change.

- **Don't show this again, everywhere.** One shared control (a 44 px checkbox row
  under a hairline) now ends every help that shows by itself: the How it works panel
  in each page's ⋯ sheet on a phone, Home's "New to Crew? Read how it works" row
  (it replaces the ✕), the Get started checklist (it replaces Hide) and the Start a
  session guide. Ticked help stays until you leave the page or close the sheet, then
  stops showing by itself. "?" popovers are unchanged.
- **Still there on demand.** Every page's ⋯ has **How it works**. When that page's
  help is hidden it opens in place with the box ticked; untick it to let it show by
  itself again.
- **Show all help again.** Settings has a new Help section with **Show all help
  again**: it clears every hide (including the session guide's) and confirms with
  "All help will show again".
- **Hides follow you.** They are kept on the server in `crew_settings.hidden_help`,
  so they hold across browsers; Home's old per-browser hides carry over once.
- **Ids in inline code link.** A code span that holds exactly one record id (as
  agents often write `` `abc123def456ghi` ``) reads as the record's title and opens
  it, like bare ids since 0.29.0. Right after a link to the same record (a title link
  followed by its id in backticks) the id itself is the link, with the title as its tooltip, so
  the sentence doesn't repeat the title. Unknown ids stay ordinary code; fenced code
  blocks, written links and the stored text are untouched, and every id on the page
  still resolves in one batched read.
- **For agents.** `settings.update` also accepts `hidden_help` (up to 100 ids of
  1–64 characters `a-z 0-9 _ . -`; `[]` or `null` clears it).

## Upgrade

Back up first, then replace the binary or image, upgrade paired clients to 0.37.0
and refresh MCP tool schemas; see [Crew 0.36.0 to 0.37.0](../upgrades.md). Older
binaries refuse the migrated database; rollback restores the backup. From 0.35.0 or
earlier, follow the earlier notes first.
