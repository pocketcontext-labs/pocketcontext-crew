# Crew 0.38.0

Review markup: agents mark each paste-ready text inside a review option (and in
notes, comments and task drafts) so the owner copies, counts and comments on that
text alone. One contrast fix. No data migration, protocol or managed block change;
run `skill` once and refresh MCP schemas.

- **Three blocks agents write, read as data.** Inside an option body, a review draft,
  a note, a comment or a task draft, agents wrap text in Markdown container blocks:
  `:::variant{channel=linkedin}` (channels linkedin, x, email, whatsapp, slack,
  generic; optional `limit=N`), `:::copy{label="WhatsApp reply"}` and `:::note`,
  each closed by `:::`. This is not MDX: no JSX, no code, no raw HTML. Anything
  outside this closed vocabulary (unknown names, bad attributes, nesting, `:word`
  in prose) renders exactly as written, so existing text is unchanged.
- **Per-block Copy, count and feedback in reviews.** Each variant or copy block is
  its own card with its channel name or label, a character count against the
  channel limit (LinkedIn 3,000, X 280 with every URL counted as 23; over the
  limit the count turns red with "too long"), Copy (plain text, only that block) and
  a feedback button that opens a field under the block. The option header is
  checkbox, label and ⋯ (Copy all variants, Feedback on the whole option). An
  option without blocks shows one unlabelled block with Copy and feedback in the
  same place. Notes for the reviewer are shown in grey and never copied or counted.
  Variants sit side by side on a desktop and stack on a phone. Outside reviews the
  same blocks get Copy and the count, without feedback. Compact previews and the
  whole-text Copy drop the markers.
- **Feedback as data.** Per-block feedback is stored in
  `option_decisions[].feedback` as `[{target, note}]` (target is the channel or
  `copy-<n>`), validated against the frozen option body; reads add the derived
  `feedback_text` lines (`[linkedin] …`). The decided review shows each feedback
  under its block and the summary counts them. Delegated `review.decide` accepts
  the same field. `review_outcome` wakes now carry `review_id`; payloads stay
  reference-only, so the agent reads the review for the feedback.
- **Markup warnings.** `review.request`, `note.create`/`note.update`,
  `task.create`/`task.update` and `task.comment` return `warnings`
  (`[{code, option, field, line, opener, message}]`, codes
  `review_markup_unknown_directive`, `review_markup_invalid_attribute`,
  `review_markup_nesting`, `review_markup_duplicate_channel`,
  `review_markup_unclosed`) without blocking. A later release will refuse invalid
  review markup with 400 `review_markup_invalid`. Capabilities describe the markup.
- **Bot instructions.** The `pocketcontext-crew` skill tells agents to use one option
  per draft and one variant per platform inside it, to put only the exact text in
  each block, and where per-block feedback arrives.
- **Higher-contrast review icons.** Copy and feedback icons use the dark text colour
  with 2 px strokes on 44 px targets, and the unchecked option checkbox has a darker
  2 px border.

## Upgrade

Replace the binary or image, run `skill` once, refresh MCP tool schemas and upgrade
paired clients to 0.38.0; see [Crew 0.37.2 to 0.38.0](../upgrades.md).
