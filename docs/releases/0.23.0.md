# Crew 0.23.0

Releases become ordinary labels, live shared links get an **Open** button, and
archived update drafts say whether they were merged or discarded. One data
migration needs a complete backup before upgrading. Run `skill` once and refresh
MCP tool schemas. Protocol 3 and the managed webhook instruction block are
unchanged, so delivery doesn't pause for this upgrade.

## Releases are labels

Crew is a general task board, so tasks no longer have a dedicated Release field.
A release is a label such as `release-0.23.0`.

- The migration adds `release-<value>` to every task that had a release (unless
  it already carried that label) and drops the `release` column. It doesn't
  change when tasks were last updated, so the Done column keeps its order.
- The task dialog has no Release field, Filters has no release option, cards no
  longer show "Shipped in X", and the search no longer reads `release:`. Use the
  label filter or `label:release-0.23.0`.
- The Done column is one list, most recently changed first: the last 7 days by
  default, with **Show older**. Choosing a label shows that label's older closed
  tasks too, so a release label finds all of that release's work.
- A 0.22.0 address with `release=<release>` opens as the label filter
  `release-<release>`.
- Agents: `crew_write` and `crew_read` refuse `release` with HTTP 400 and
  `release_field_removed`, pointing to labels. The coding session's close step
  adds the label `release-<version>` together with `status: done` and
  `review_mode: in_session`. The SQL view `tasks` has no `release` column.

## Shared page

- **Open** next to Copy link on live cards opens the public page in a new tab.
  Crew doesn't count that visit as a view (the browser marks it as coming from
  Crew itself), so the view count stays about recipients. Drafts, revoked,
  expired and archived items have no Open.
- An archived update draft whose content went live through **Update content
  (same link)** now says **Merged into <title> on <date>**, and explains that
  Restore brings back the draft only. A discarded update draft still says
  "Update of: <title>". Reads add the derived `merged_into` and `merged_at`,
  which also work for drafts merged under 0.22.0.

## Tests

- The reader tests wait up to 5 seconds for asynchronous assertions instead of
  1 second, which fixes intermittent failures on slow runners such as Windows CI.

## Upgrade

Follow [Crew 0.22.0 to 0.23.0](../upgrades.md). Back up the complete stopped
project and private webhook key before replacing the binary or image. Upgrade
paired clients to match. Older binaries refuse the migrated database, and rollback
restores the complete pre-upgrade backup, losing changes made since it.
