# Crew 0.31.0

Reader only. No data migration, protocol, managed block, skill or capabilities
change.

- **Swipe between items opened from a list.** A task, note, bucket, agent or review
  dialog opened from a list now steps through that list without closing: swipe left
  for the next item and right for the previous one on a phone, or use Left and Right
  and the new previous/next pill after the title on a wider screen. The list is the
  page under the dialog as you see it, in its current filter and sort: the board's
  visible cards, the Notes page's notes or bucket cards, the Agents page, pending
  reviews (or past decisions) on Approvals, and Search results. A review link such
  as `#/approvals/<id>` steps through the Approvals page. The address follows the
  item shown (replaced, so Back still returns to the list); at either end the body
  bounces and nothing wraps. A dialog with no list behind it, such as a review opened
  from Home, does not step.
- **Guard rails.** Unsaved changes, including a typed Decision note, ask before
  moving; a swipe never saves, approves, requests changes or rejects. Swipes are
  ignored at the screen edges (so iOS Back still works), when mostly vertical (the
  dialog scrolls), when short or slow, in fields, while typing or selecting text, in
  content that scrolls sideways, and in the image viewer, which keeps its own swipe.
  The non-image file preview now steps through files with the same swipe.
- **Decisions stay put.** A pending review's Decision note and buttons are pinned to
  the bottom of the dialog like the editors' save bar, with Approve on its own row
  and Request changes and Reject side by side, so they do not move from one review
  to the next. The header keeps one row on phones; the previous/next pill appears
  from 681 px.

## Upgrade

Replace the binary or image and upgrade paired clients to 0.31.0; see
[Crew 0.30.1 to 0.31.0](../upgrades.md). From 0.29.0 or earlier, follow the
0.29.0 to 0.30.0 notes first.
