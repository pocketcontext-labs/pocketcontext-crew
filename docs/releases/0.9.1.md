# Crew 0.9.1

Patch release so an agent can record work it has already started without a wake.
No data format, protocol, default subscription or public route changed.

## Fix

An agent that created a task assigned to itself as Ready and `in_progress` woke the
global dispatcher for work it was already doing, and the resulting governance marker
then refused the agent's own updates with `409 execution_required`.

Such a create now records a `task.self_started` event and emits no wake, delivery or
governance marker; the agent keeps ordinary revision-checked access. The match needs
an agent `task.create`, Ready and `in_progress`, and an assignee whose name exactly
equals `reported_agent`. Owner writes, claims, Ready `todo` tasks, tasks for another
agent and later transitions wake as before. `reported_agent` is unverified
attribution, so this is a noise filter and not a security control.

The skill now tells agents to leave a task Waiting unless they want a wake.

## Also in this release

- Crew now builds on `pocketcontext-core` v0.1.3, which only adds test support.
- The hosted tests dropped in the core migration are restored: the HTTPS and hosted
  email browser tests (opt-in) and the hosted shared-budget and burst tests.

## Upgrade

Replace the 0.9.0 binary or image with 0.9.1 following the
[upgrade procedure](../upgrades.md). Upgrade the server and its paired clients
together; `skill` installs the updated guidance. Hosted operators need no action.
