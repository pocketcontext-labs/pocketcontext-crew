# Crew 0.28.0

Review links: an agent can send the owner one link that opens a review's Review
draft dialog directly. No data migration, protocol or managed block change; run
`skill` once and refresh MCP tool schemas.

- **`#/approvals/<review-id>` opens the review.** The link shows the Approvals page
  with that review's Review draft dialog on top, the same dialog a card opens, so
  on a phone Approve, Request changes and Reject are one tap away. A decided or
  withdrawn review opens read-only with its outcome and, once decided, who decided
  and when ("Approved … by you."). An unknown review id stays on the Approvals
  page with a "Review not found." notice. A review newer than the page's last load
  is read by id.
- **The address follows the dialog.** Clicking an Approvals card (pending or past
  decision) puts its review link in the address, so it can be copied and shared.
  Closing the dialog or deciding replaces the address with `#/approvals`, so the
  browser's Back never reopens the review.
- **Sign-in comes back to the review.** A signed-out visit to a review link signs
  in (password or emailed link) and then opens the same review.
- **Reviews carry their link.** Review reads (`crew_read` collection `reviews`) and
  the `review.request`, `review.decide` and `review.withdraw` results include the
  derived `path` (`#/approvals/<id>`) and, when the install has a domain, `url`;
  both can be requested in `fields`. Like task and note links, they are derived on
  the way out and never stored, put in events or in webhook payloads. The
  capabilities schema, `docs/crew.md` and the skill tell agents to send the owner
  this `url` for an approval instead of building one.

## Upgrade

Replace the binary or image, upgrade paired clients to 0.28.0, run `skill` once and
refresh MCP tool schemas; see [Crew 0.27.2 to 0.28.0](../upgrades.md). From 0.27.1
or earlier, follow the earlier notes first.
